# Data and Model Sources

This part records **every outside resource the project uses**: the data the model was trained on,
the pretrained model it started from, the comparison model, the documents made for testing, and
the software libraries. Each entry says where it comes from, its licence, and exactly how it was used.

**No real personal data was used anywhere.** The training data is synthetic (machine-generated),
and all test and sample documents are fictional documents generated by this project.

## 1. Summary

| Resource | Used for | Source | Licence | Real personal data? |
|---|---|---|---|---|
| NVIDIA Nemotron-PII (dataset) | Training, validation and testing of the AI model; testing the rules | Hugging Face Hub | CC BY 4.0 | No, fully synthetic |
| distilbert-base-cased (model) | The pretrained model that was fine-tuned | Hugging Face Hub | Apache 2.0 | Not applicable |
| dslim/distilbert-NER (model) | Comparison baseline, and fallback when the trained model is missing | Hugging Face Hub | Apache 2.0 | Not applicable |

| 5 sample files | Trying the app | Generated by this project | Part of the project | No, fictional |
| 500 extra ORG documents | Extra training data for company names (350), plus validation (50) and test (100) | Written by the team (`data/extra/`) | Part of the project | No, fictional |

### 2.1 Files that were downloaded

The script `scripts/01_prepare_data.py` downloads two files. The addresses are stored in
`config/config.yaml` under `data.download_urls`.

| File | Saved as | Size | Rows |
|---|---|---|---|
| Train file | `train.parquet` | 156 MB | 100,000 |
| Test file | `test.parquet` | 151 MB | 100,000 |

Download addresses:

```
https://huggingface.co/datasets/nvidia/Nemotron-PII/resolve/main/data/train-00000-of-00001.parquet
https://huggingface.co/datasets/nvidia/Nemotron-PII/resolve/main/data/test-00000-of-00001.parquet
```

They are saved in `data/raw/nemotron_pii/`. This folder is not put in the Git repository because
of its size; anyone can download the files again with the script. The prepared documents that the
project actually uses (`data/processed/`, 33 MB) are in the repository.

### 2.2 What the dataset contains

Measured by our own data pipeline (stored in `reports/metrics/data_summary.json`):

- 200,000 documents in total: forms, invoices, emails, letters, records and similar texts.
- 58 domains (for example insurance, finance, banking, telecommunications) and 2,636 document types.
- About half structured and half unstructured text; half use US-style personas and half international ones.
- Average length about 980 characters; average 8.4 labelled items per document.
- 55 different label types, each with exact character positions in the text.
- Each document identifier appears twice, once in a US version and once in an international version.

### 2.3 How much of it was used

| Step | Number of documents |
|---|---|
| Downloaded | 200,000 |
| Removed: 1 duplicate text and 41 over-long documents (more than 6,000 characters) | 42 |
| Remaining after cleaning | 199,958 |
| **Used for training** (random sample from the train file) | **20,000** |
| **Used for validation** (from the train file, no overlap with training) | **2,000** |
| **Used for testing** (from the separate test file) | **3,000** |

The samples are drawn with a fixed random seed (42), so the same documents are selected every time.
The test documents come from a separate file and were never seen during training.
Only 25,000 of the 199,958 documents were used. This kept training short (17 minutes) and was
already enough for good results; using more is a possible improvement.

### 2.4 Which labels were used

The dataset has 55 label types. The AI model was trained on 8 of them, mapped to 4 categories.
The mapping is stored in `config/config.yaml` under `data.label_map`.

| Dataset label | Count in the dataset | Our category |
|---|---|---|
| `first_name` | 143,366 | PERSON |
| `last_name` | 103,547 | PERSON |
| `company_name` | 140,147 | ORG |
| `country` | 51,229 | LOCATION |
| `city` | 37,648 | LOCATION |
| `state` | 37,374 | LOCATION |
| `county` | 14,917 | LOCATION |
| `street_address` | 33,708 | ADDRESS |

A first name directly followed by a last name is merged into one PERSON item.

Four more labels were used **only to test the rules**, never for training:

| Dataset label | Count in the dataset | Tests the rule for |
|---|---|---|
| `email` | 103,806 | EMAIL |
| `phone_number` | 48,923 | PHONE |
| `fax_number` | 13,780 | PHONE |
| `credit_debit_card` | 21,911 | CREDIT_CARD |

The remaining 43 labels (for example `date`, `url`, `occupation`, `date_of_birth`, `password`)
are ignored in this version.

### 2.5 Why this dataset was chosen

- The licence is clear and allows this use (CC BY 4.0, with attribution).
- It is fully synthetic, so the project's rule "no real personal data" is respected.
- The texts look like personal and business documents, not like news articles.
- The labels come with exact character positions, the same format the project uses internally.

Other datasets that were considered and not used:

| Dataset | Decision |
|---|---|
| CoNLL-2003 | Rejected: news text, and licence restrictions |
| ai4privacy PII-masking | Rejected: the licence information differs between versions |
| Gretel PII masking v1 | Not chosen: smaller, and its licence could not be confirmed during the research |

The team looked at three more datasets later (November 2026) and recorded these notes:

| Dataset | Team's note | Status |
|---|---|---|
| [ai4privacy/pii-masking-openpii-1.5m](https://huggingface.co/datasets/ai4privacy/pii-masking-openpii-1.5m) | 1.2 million rows, but would need a lot of work to fit our labels | Not used |
| [DFKI-SLT/few-nerd](https://huggingface.co/datasets/DFKI-SLT/few-nerd) | Promising for organisations (about 500,000 rows) | Not used yet; a candidate for future ORG work (see the weak-points document) |
| [gretelai/gretel-pii-masking-en-v1](https://huggingface.co/datasets/gretelai/gretel-pii-masking-en-v1) | About 60,000 rows, similar style and purpose, but one industry only | Not used |

The team concluded that Nemotron-PII still covers the bigger picture best, and wrote its own ORG
documents instead (Section 5b). The licences of these three datasets must be checked before any of
them is used.

### 2.6 Known limits of this dataset

- The text is synthetic. Real documents can be messier and more varied.
- Many names, addresses and formats follow US conventions.
- English only.
- Only the values that the generator inserted are labelled. A name that appears in the text for
  another reason may be unlabelled.
- `company_name` covers companies. Universities, hospitals and government bodies are rare,
  which explains the model's weakness with such names.

## 3. The pretrained model: distilbert-base-cased

| | |
|---|---|
| **Web page** | https://huggingface.co/distilbert/distilbert-base-cased |
| **Publisher** | Hugging Face |
| **Licence** | Apache 2.0 |
| **Size** | About 65 million parameters |
| **Reference** | Sanh, V., Debut, L., Chaumond, J., Wolf, T. (2019). *DistilBERT, a distilled version of BERT: smaller, faster, cheaper and lighter.* |

This model already understands general English. According to its model card it was pretrained on
English Wikipedia and a large collection of books (BookCorpus). It was **not** trained to find
personal information. Our project added a new output layer with 9 classes and fine-tuned the
whole model on the 20,000 Nemotron-PII training documents (version 2 also on 350 of the team's
ORG documents, Section 5b). The result is saved in
`models/privacylens-ner/`.

It was chosen because it is small enough to train on a laptop GPU in minutes, and because it is
"cased" (it sees capital letters), which matters for recognising names.

## 4. The comparison model: dslim/distilbert-NER

| | |
|---|---|
| **Web page** | https://huggingface.co/dslim/distilbert-NER |
| **Licence** | Apache 2.0 |
| **Trained on** | News-style text with general labels for people, organisations and places (according to its model card) |

It has two roles and was **not** used for training:

1. **Baseline.** It was tested on the same 3,000 test documents to show what fine-tuning adds
   (F1 0.687 against 0.961 for our model, version 2; 0.956 for version 1).
2. **Fallback.** If the trained model is missing on a computer, the app downloads and uses this
   model so that it still works, and tells the user.

## 5. Documents created by the project for testing

The script `scripts/03_make_synthetic_docs.py` (code in `src/synthetic_data.py`) writes fictional
documents from 14 templates: letters, CVs, forms, emails, chat messages and others.

- 60 documents: 20 for development (tuning) and 40 for the final test. Random seed 303.
- Every name, company, address, phone number, ID and bank number is invented. Email addresses use
  reserved example domains.
- The correct answers ("gold labels") are written automatically, because the generator knows where
  it placed each value. They are stored in `data/gold/`.
- The same script also creates the five sample files in `data/samples/`.

These documents were written by the project, so they are not an independent source.
They are useful because their style differs from the training data.
